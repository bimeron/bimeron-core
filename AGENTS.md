# Documentation instructions

All Markdown documentation and user-facing text must be in English. Keep third-party attribution and license terms intact. Do not add private credentials, old repository history, or a remote before the new repository URL is provided.

# Development workflow

- Write documentation, commit messages, issues, pull requests, and other project artifacts in English.
- Use Conventional Commits. Commits may be created without prior approval, and a co-author may be credited when appropriate. Push only when explicitly requested.
- Track substantial changes in issues and implement them on separate branches. Discuss the change with the user before opening a pull request.
- Use CI. Treat documentation, test coverage, and benchmarks as important parts of project work.
- Consult the user on architectural decisions. Present options, tradeoffs, and constructive criticism before choosing an approach.
- Record architectural decisions in ADRs when they warrant a lasting explanation of the context, alternatives, and tradeoffs.
- Recommend a reasoning effort change when warranted, including the level to use and why.
- Use relevant skills when appropriate, especially `ponytail` for coding tasks.
